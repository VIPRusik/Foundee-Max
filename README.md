# Foundee-Max

Чат-бот в мессенджере MAX с мини-приложением для быстрого закрытия сезонных и срочных вакансий
в рознице, общепите и АПК.

> Бот в MAX: [https://max.ru/t715_hakaton_max_bot](https://max.ru/t715_hakaton_max_bot)

## Назначение решения

Малому бизнесу — кафе, магазинам, фермерским хозяйствам — регулярно нужны люди «на завтра»:
на сезон, смену или подработку. Размещение на крупных площадках занимает время и требует
разбирать много нерелевантных откликов.

Foundee-Max сводит спрос и предложение по нескольким параметрам прямо в MAX:

- **Работодатель** отвечает на несколько коротких вопросов (в основном кнопками). Бот сохраняет вакансию
  и сразу показывает трёх наиболее подходящих кандидатов.
- **Соискатель** выбирает сферу, город и формат занятости и получает подходящие вакансии — в том числе
  созданные работодателями в этом же боте.

Результаты можно открыть карточками в мини-приложении.

## Основной пользовательский сценарий

Работодатель:

1. `/start` → «💼 Я работодатель» (роль запоминается).
2. Сфера (кнопки) → должность (текст) → город (текст) → формат занятости (кнопки) → срочность (кнопки)
   → оплата (текст или «Пропустить») → телефон для связи (только при первой вакансии).
3. Бот сохраняет вакансию и показывает до 3 подходящих кандидатов с контактами.
4. «📋 Открыть карточками» открывает мини-приложение со списком.
5. «📋 Мои вакансии» — список своих вакансий (не более 3): повторный подбор кандидатов 🔍 или удаление 🗑.

Соискатель:

1. `/start` → «🙋 Я ищу работу».
2. Сфера (кнопки) → город (текст) → формат занятости (кнопки).
3. Бот показывает до 3 подходящих вакансий с контактами работодателя и кнопкой мини-приложения.

Сменить роль можно командой `/change_role` или кнопкой «🔁 Сменить роль» — вакансии при этом сохраняются.

## Состав и архитектура

```
MAX (пользователь)
   │  long polling (platform-api2.max.ru, TLS с сертификатом Минцифры)
   ▼
bot.js ── src/handlers.js ── src/scenarios.js ── src/matching.js
                                   │                  │
                                   ├─ src/steps.js    ├─ data/candidates.json      (тестовые кандидаты)
                                   ├─ src/users.js ───┼─ data/users.json           (роли, телефон)
                                   └─ src/vacancies.js┼─ data/vacancies.json       (вакансии пользователей)
                                                      └─ data/demo-vacancies.json  (демо-вакансии)
   │
   │  кнопка open_app, данные карточек в параметре ?data=
   ▼
miniapp/ (React + MAX UI, статический хостинг Vercel)
```

| Модуль | Назначение |
| --- | --- |
| `bot.js` | Точка входа: проверка окружения, создание бота, регистрация обработчиков, список команд |
| `src/config.js` | Чтение переменных окружения |
| `src/http.js` | `fetch` с сертификатом Минцифры и включённой проверкой TLS |
| `src/handlers.js` | Маршрутизация команд, нажатий кнопок и текста; обработка устаревших кнопок и ошибок |
| `src/steps.js` | Описание шагов опроса: вопрос, варианты ответа, проверка ввода, следующий шаг |
| `src/scenarios.js` | Сценарии работодателя и соискателя, меню, «Мои вакансии» |
| `src/matching.js` | Подбор кандидатов и вакансий |
| `src/users.js`, `src/vacancies.js`, `src/storage.js` | Хранение ролей и вакансий в JSON-файлах |
| `src/keyboards.js`, `src/format.js`, `src/miniapp.js` | Клавиатуры, тексты ответов, ссылка на мини-приложение |
| `miniapp/` | Мини-приложение: карточки кандидатов или вакансий, телефон по кнопке |

**Алгоритм подбора.** Обязательное условие — совпадение сферы. Остальные параметры дают баллы:
город +3, формат занятости +2, срочность +1. Возвращаются 3 лучших результата.

## Запуск с использованием Docker
Для запуска решения нужен Docker и Docker Compose.

1. Переделать `.env.example` -> `.env` и заполнить параметры окружения (токен бота): 
```bash 
cp .env.example .env 
```

2. Запуск 
```bash 
docker-compose up -d --build
```

3. Проверка
```bash 
docker-compose logs -f
```

4. Для остановки 
```bash 
docker-compose down
```

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
| --- | --- | --- | --- |
| `BOT_TOKEN` | да | — | Токен бота MAX |
| `MINIAPP_URL` | нет | `https://max-miniapp-eight.vercel.app/` | HTTPS-адрес мини-приложения |
| `CA_CERT_PATH` | нет | `certs/russian_trusted_bundle.pem` | Сертификаты Минцифры для API MAX |
| `DATA_DIR` | нет | `data` | Каталог с JSON-данными |

Рабочие токены в репозитории не хранятся, `.env` добавлен в `.gitignore`.

## Порты

Бот получает обновления через long polling и **не открывает входящих портов**.
Мини-приложение размещено на внешнем HTTPS-хостинге (Vercel) и в Docker не запускается.

## Зависимости

Бот (Node.js ≥ 20, в Docker — `node:22-alpine`), версии зафиксированы в `package-lock.json`:

- `@maxhub/max-bot-api` — официальная библиотека ботов MAX;
- `undici` — HTTP-клиент с поддержкой собственного набора корневых сертификатов;
- `dotenv` — загрузка `.env`.

Мини-приложение (`miniapp/package-lock.json`): `react`, `react-dom`, `@maxhub/max-ui`, сборка — `vite`.

## Внешние сервисы и интеграции

| Сервис | Назначение | Условия |
| --- | --- | --- |
| MAX Bot API (`platform-api2.max.ru`) | Получение сообщений и отправка ответов | Токен бота; сертификаты Минцифры лежат в `certs/` |
| Vercel | HTTPS-хостинг мини-приложения | Мини-приложение должно быть привязано к боту на платформе MAX для партнёров |

Интеграций с внешними кадровыми системами (например, «Работа России») в MVP **нет** — используются
тестовые данные, см. ниже.

## Работа с данными

- `data/candidates.json` — **тестовые** (вымышленные) кандидаты, 29 записей. Только чтение.
- `data/demo-vacancies.json` — **тестовые** вакансии, 12 записей. В ответах бота помечены «демо».
- `data/vacancies.json` — вакансии, созданные работодателями в боте. Привязаны к `user_id` MAX,
  не более 3 на пользователя. Создаётся автоматически.
- `data/users.json` — роль пользователя и телефон для вакансий. Создаётся автоматически.

Файлы, которые создаёт бот, не попадают в git и Docker-образ; каталог `data/` монтируется в контейнер,
поэтому данные сохраняются между перезапусками. Запись идёт через временный файл, чтобы при сбое
не остался повреждённый JSON.

Состояние незавершённого опроса хранится в памяти: после перезапуска бота опрос начинается заново,
а нажатие старой кнопки даёт подсказку вместо ошибки.

Мини-приложение не имеет своего API: бот передаёт ему найденные карточки в параметре ссылки
(JSON в base64url). Поэтому мини-приложение показывает ровно то, что бот нашёл в этом диалоге.

## Пошаговый сценарий проверки

1. Откройте бота в MAX и нажмите «Начать» (или отправьте `/start`).
2. Нажмите «💼 Я работодатель» → «☕️ Общепит» → напишите `Бариста` → `Москва` →
   «Полная занятость» → «🔥 Сегодня-завтра» → «Пропустить» → `+7 900 123-45-67`.
3. Ожидаемо: «✅ Вакансия «Бариста» сохранена…» и три кандидата из Москвы (Анна, Павел, Ольга).
4. Нажмите «📋 Открыть карточками» — откроется мини-приложение с теми же кандидатами; телефон
   показывается по кнопке.
5. Нажмите «📋 Мои вакансии» → 🔍 у вакансии — повторный подбор; 🗑 — удаление.
6. Нажмите «🔁 Сменить роль» → «🙋 Я ищу работу» → «☕️ Общепит» → `Москва` → «Полная занятость».
7. Ожидаемо: первой в списке — вакансия «Бариста», созданная на шаге 2, затем демо-вакансии.

## Примеры ожидаемого поведения

| Действие | Реакция бота |
| --- | --- |
| Текст вместо нажатия кнопки | «Выберите вариант кнопкой ниже 👇» и повтор вопроса с кнопками |
| Слишком короткая должность или город из цифр | Пояснение с примером, вопрос повторяется |
| Телефон `12345` | «Не похоже на российский номер…»; `8 (916) 123-45-67` сохраняется как `+7 916 123-45-67` |
| Нажатие кнопки из старого сообщения | Уведомление «Эта кнопка уже неактуальна» и возврат к текущему шагу |
| Четвёртая вакансия | Сообщение о лимите и список вакансий с кнопками удаления |
| Неизвестная команда | «Не знаю такой команды» и справка |
| «заново» на любом шаге | Опрос начинается сначала |
| Внутренняя ошибка | «Что-то пошло не так… Нажмите /start» — бот продолжает работать |

## Известные ограничения (что намеренно не реализовано в MVP)

- Кандидаты и демо-вакансии — тестовые данные; реальной интеграции с кадровыми системами нет.
- Соискатель не создаёт анкету, работодатели видят только тестовых кандидатов.
- Нет откликов и переписки внутри бота — контакт по телефону.
- Хранение в JSON-файлах рассчитано на один экземпляр бота; для масштабирования нужна БД.
- Long polling подходит для MVP; для промышленной эксплуатации нужен webhook.
- Подбор по городу — сравнение строк, без справочника населённых пунктов и расстояний.

## Остановка и повторный запуск

```bash
docker compose down            # остановка
docker compose up -d           # повторный запуск (данные в ./data сохраняются)
docker compose up -d --build   # запуск после изменения кода
```

## Запуск без Docker

```bash
npm ci
cp .env.example .env   # укажите BOT_TOKEN
npm start
```

## Мини-приложение

```bash
cd miniapp
npm ci
npm run dev     # локальная разработка
npm run build   # сборка в miniapp/dist
```

Собранное приложение разворачивается на Vercel; адрес указывается в `MINIAPP_URL`
и в настройках бота на платформе MAX для партнёров.
